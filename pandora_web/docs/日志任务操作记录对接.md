# 日志与任务操作记录对接

本文件供管理员前端维护与接口联调使用。管理员端只调用现有查询接口，不新增审计来源参数或要求后端回传额外标识。当前源码核对基于后端 `f8d31ad`（已合入 `main d979395`）和手机端 `v2.0 ed5a0d5`。

## 页面范围与动作

- 操作记录页仅包含工作日志 `LOG` 和派发任务 `TASK`，默认与重置均查询工作日志。
- 保留已确认的 5 项日志动作和 9 项任务动作，日志没有删除动作，自建任务不纳入。
- 任务动作“更新进度”在界面统一显示为“标记为已完成”，请求仍发送后端原值。
- 数据以接口实际返回为准，列表不删除单页记录来伪造总数；不根据时间相近合并操作。
- Web 提供筛选、分页、刷新和详情，不增加手机端业务操作、任务审批或数据恢复页面。

下表路径均带 `/api` 前缀，第一列为发送给后端的精确动作值。

| 记录类型与动作 | 移动端入口和条件 | 请求 |
| --- | --- | --- |
| `LOG` 新增日志 | 用户第一次点击「保存草稿」，可选择北京时间今天及前两天 | `POST /logs`，带 `logDate` |
| `LOG` 修改日志 | 用户编辑本人已有草稿并保存 | `PUT /logs/{id}` |
| `LOG` 提交日志 | 用户点击「正式提交」，正文保存计入本次提交 | 当前先保存正文，再 `POST /logs/{id}/submit` |
| `LOG` 日志点评 | 直属上级发送点评 | `POST /logs/{id}/comments`，无父点评 |
| `LOG` 回复点评 | 日志作者选择上级的点评并回复 | `POST /logs/{id}/comments`，带 `parentId` |
| `TASK` 提交派发申请 | 新建派发，从人员列表选接收人后提交 | `POST /tasks/dispatch-requests` |
| `TASK` 编辑待审派发申请 | 在本人发布记录中编辑待审申请 | `PUT /tasks/dispatch-requests/{requestId}` |
| `TASK` 撤回派发申请 | 在本人发布记录中撤回待审申请 | `DELETE /tasks/dispatch-requests/{requestId}`，返回 `WITHDRAWN` |
| `TASK` 提交修改申请 | 编辑本人已发布且无待审变更的任务 | `POST /tasks/{taskId}/change-requests`，`action=UPDATE` |
| `TASK` 提交删除申请 | 对本人已发布且无待审变更的任务申请删除 | `POST /tasks/{taskId}/change-requests`，`action=DELETE` |
| `TASK` 更新进度 | 手机端 `v2.0` 的接收人入口为「标记为已完成」，管理端筛选、列表和详情同样显示「标记为已完成」，查询仍使用后端原值 `更新进度` | `POST /tasks/assignments/{assignmentId}/progress-updates` |
| `TASK` 申请完成检查 | 接收人完成任务后，尚未申请或被退回时可申请 | `POST /tasks/assignments/{assignmentId}/review-invitations` |
| `TASK` 通过检查 | 派发人处理待检查任务 | `POST /tasks/assignments/{assignmentId}/review`，`result=APPROVED` |
| `TASK` 退回检查 | 派发人处理待检查任务，填写退回原因 | 同一检查接口，`result=RETURNED` |


手机端入口仅作为管理员端动作选项的核对依据。后端禁止修改已提交日志，手机端按钮与此规则的差异由手机端同学处理，本轮不扩展相关功能。

## 已有查询接口

`GET /api/audits`

| 参数 | 含义 |
| --- | --- |
| `objectType` | 必须明确发送 `LOG` 或 `TASK` |
| `actor` | 可选，操作人姓名或账号 |
| `action` | 可选，上表中的精确动作值；省略时按后端现有规则返回该类型的记录 |
| `from`、`to` | 可选，`YYYY-MM-DD`，按北京时间包含起止日期 |
| `page`、`size` | 从 1 开始的页码和每页条数，页面每页 10 条 |

统一响应 `{code,message,data}`，分页 `data` 为 `{items,page,size,total}`。空列表是正常结果。返回的业务类型与请求不一致时明确报错。

`GET /api/audits/{id}`

详情直接按编号查询。前端拒绝显示日志、任务之外的记录。通用字段如下。

| 字段 | 含义 |
| --- | --- |
| `id` | 操作记录编号 |
| `actor` | 操作人文字 |
| `action` | 后端动作原值 |
| `target` | 操作对象说明 |
| `time` | 带时区的时间，界面按北京时间显示 |
| `result` | 服务端记录的结果，列表和详情展示，不提供结果筛选 |
| `objectType`、`objectId` | 业务类型和原业务编号 |
| `source` | 服务端记录的来源；按实际返回展示 |
| `summary` | 简要操作说明 |
| `changes` | 详情中的字段变化数组，元素为 `{field,before,after}` |

历史详情缺少 `changes` 或返回 `null` 时按空数组展示；错误数组结构明确报错。正文变化仅展示服务端提供的摘要或标记，不用于还原数据。任务删除后的历史详情是否仍可读取，以实际服务端结果为准。

## 开户与资料约束

管理员新开户前后端均要求身份证号必填，校验结构、出生日期和校验位，小写 x 归一化为大写。性别选填，不预选。保留现有账号，不增加补录接口或待补全流程，不把证件原文写进审计。

## 联调

开发环境的“接口联调”提供一键自动测试，覆盖管理员端 21 个接口以及团队成员筛选入口。自动获取已有日志、任务记录编号验证详情；没有数据时明确标记未验证，不生成假的日志或任务记录。

自动测试会调用写接口创建专属测试账号、部门、团队和事件，执行修改、启停、改密、独立登录与注销，并回查结果。账号结束后停用，临时部门和团队删除；用户和事件没有删除接口，保留记录及收尾状态会列入报告。当前管理员会话不作为注销和改密对象。

完整接口清单、版本依据与使用方法见[接口核对与联调](接口核对与联调.md)。前端自动化的隔离响应测试不等同于真实服务器联调。
