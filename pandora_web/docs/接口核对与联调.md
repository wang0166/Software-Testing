## 管理员前端接口清单

所有路径均以 `/api` 为前缀。联调页自动沿用当前服务前缀和认证，敏感字段不进入结果历史。

| 模块 | 方法与路径 | 参数与用途 |
| --- | --- | --- |
| 会话 | `POST /auth/login` | 自动生成专属联调账号及密码，检验登录响应，令牌仅用于测试会话 |
| 会话 | `GET /auth/me` | 当前管理员角色和权限 |
| 会话 | `POST /auth/logout` | 自动注销本次测试账号的会话，不退出当前管理员 |
| 用户 | `GET /users` | `keyword`、`role`、`status`、`departmentId`、`teamId`、`page`、`size` |
| 用户 | `GET /users/{id}` | 用户详情 |
| 用户 | `POST /users` | `username`、`password`、`realName`、`phone`、`idNumber`、`role`、组织归属与可选性别 |
| 用户 | `PUT /users/{id}` | `realName`、`role`、`departmentId`、`teamId`；组织归属空值为 `null` |
| 用户 | `PATCH /users/{id}/status` | 数字 `status`，1 启用、0 停用 |
| 用户 | `PUT /users/{id}/password` | `password`；重置密码并按服务端策略撤销会话 |
| 组织 | `GET /companies` | 获取实际公司编号 |
| 组织 | `GET /departments` | 部门列表、介绍和公司归属 |
| 组织 | `POST /departments` | `name`、`companyId`、可选 `description` |
| 组织 | `DELETE /departments/{id}` | 删除部门，服务端检查关联约束 |
| 组织 | `GET /teams` | 团队列表、介绍和部门归属 |
| 组织 | `POST /teams` | `name`、`departmentId`、可选 `description` |
| 组织 | `DELETE /teams/{id}` | 删除团队，服务端检查关联约束 |
| 事件纪 | `GET /company-matters` | `page`、`size` |
| 事件纪 | `POST /company-matters` | `title`、`content`、`sortOrder`、`startDate`、`deadline` |
| 事件纪 | `PUT /company-matters/{id}` | 同新增，时间按北京时间整点提交 |
| 操作记录 | `GET /audits` | `objectType` 固定为 `LOG` 或 `TASK`，可选 `actor`、`action`、`from`、`to` 和分页 |
| 操作记录 | `GET /audits/{id}` | 单条摘要、来源和字段变化，直接按编号读取 |

团队成员复用 `GET /users?teamId=...`，联调页单独提供入口，合计 22 个调试入口、21 个方法与路径。手机端需要的刷新会话、日志、任务等接口没有混入管理员前端联调清单。

## 使用一键自动联调

1. 启动管理员端开发服务，用真实管理员账号登录并进入“接口联调”。正式构建仍隐藏开发工具。
2. 页面开始前显示写入影响：将创建一个专属测试账号和一条带标记的测试事件。用户和事件没有删除接口，账号在结束时停用，两条记录会保留；临时部门和团队在结束时删除。
3. 点击“一键自动测试全部接口”。前端自动生成测试参数，查询真实编号，顺序执行创建、详情、筛选、修改、启停、改密、独立登录与注销，随后回查并收尾。无需输入账号密码、记录编号或请求正文。
4. 查看 22 项检查报告及“保留记录与清理结果”。每项区分通过、失败、未验证；后台响应失败、回查不符或清理失败均不会计为通过。可展开脱敏检查结果。
5. 测试日志与任务详情需要已有真实操作记录，没有数据时显示未验证，不凭空生成业务日志或任务。没有公司或组织前置数据时，对应依赖项也明确标记未验证。
6. “停止并清理”会在当前请求结束后停止后续业务测试，并尝试停用测试账号及删除测试组织。若管理员会话失效，收尾可能无法继续，应核对测试记录。

测试只修改本次创建且确认归属的记录，不复用已有员工的资料、密码或账号状态。测试登录使用独立会话，注销不会清理当前管理员的浏览器凭据。测试账号使用虚构的格式校验样例，不代表真实员工身份。

密码、令牌及个人字段在报告中隐藏，自动生成的密码仅在本轮内存中使用。演示模式禁用真实联调。开发阶段的隔离响应验证只证明前端执行及错误处理，不代替用户在目标后端运行一次完整测试。
