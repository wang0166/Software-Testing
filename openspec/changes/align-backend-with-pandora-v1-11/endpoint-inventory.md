# Mobile API gap inventory

Baseline: mobile `origin/feat/pandora-task-workflow-v1.9` at `4d26b68`; backend to implement against local `devops/docker-v1.11-aligned` at `95110b4` (upstream `origin/devops/docker` at `1cdbd43`). Current checked-out `backend` at `46a952d` has only V1–V5 migrations and is **not** the target for cloud-compatible implementation. All paths below have `/api` prefix; envelope is `{code,message,data}`. Explicit route/auth failures must use business error codes; pagination uses `{total,page,size,items}`.

| Client operation | Mobile route | Aligned branch baseline / action |
| --- | --- | --- |
| Login, restore, refresh, logout | `POST /auth/login`, `GET /auth/me`, `POST /auth/refresh`, `POST /auth/logout` | Implemented by `AuthController`/`AuthService`; verify response and disabled-account handling. |
| Password reset, request/status/change | `POST /auth/password-reset-requests`, `POST /account/password-change-requests`, `GET /account/password-change-requests/me`, `POST /account/password-change` | Implemented by `PasswordController`/`PasswordRequestService` on deployment branch; verify limiter, approvals, audit, session invalidation. Missing on local `backend`. |
| Work logs and feedback | `GET/POST /logs`, `GET/PUT /logs/{id}`, `POST /logs/{id}/submit`, `GET/POST /logs/{id}/comments` | `LogController`/`LogService`; preserve ownership, dates and pagination. |
| Statistics | `GET /stats/overview`, `GET /stats/trend`, `GET /stats/unsubmitted` | `StatsController`/`StatsService`; preserve scoped counts. |
| Personal work tasks | `GET/POST /personal-tasks`, `PUT /personal-tasks/{id}` | `PersonalTaskController`/`PersonalTaskService`; owner-scoped; distinct from daily items. |
| Legacy received/dispatched/task detail | `GET /tasks/received`, `GET /tasks/dispatched`, `GET /tasks/{id}`, `GET /tasks/assignments/{id}`, `PATCH /tasks/assignments/{id}/progress`, `POST /tasks`, `GET /tasks/recipients` | Existing `TaskController`/`TaskService`; enrich DTOs and explicitly decide whether direct `POST /tasks` remains available after approval workflow is enabled. Existing role/ownership error codes 40310/40311/40312/40313, transition conflicts 40910–40912. |
| Detailed progress and read-only subordinate history | `POST/GET /tasks/assignments/{id}/progress-updates`, `GET /tasks/subordinates/{userId}/assignments/{id}/progress-updates`, `GET /tasks/subordinates/overview` | Missing; add events, authorization, progress percentage/note and scoped hierarchy. |
| Dispatch approval and published-task changes | `POST /tasks/dispatch-requests`, `GET /tasks/dispatch-requests/mine`, `PUT/DELETE /tasks/dispatch-requests/{id}`, `POST /tasks/{id}/change-requests` | Missing; pending must not create assignments; status must be `PENDING`/`WITHDRAWN` as expected by mobile. Reviewer endpoint is not used by mobile and must be authorized for web admin. |
| Candidate recipients | `GET /tasks/recipients/all` | Missing. Mobile states everyone can submit proposals and expects company-wide candidates; current `GET /tasks/recipients` limits to direct reports with `task:dispatch`. Resolve policy before implementing. |
| Company/home/map | `GET /company-matters`, `GET /company-important-tasks`, `GET /calendar`, `GET /task-map` | Existing `ContentController`/`CalendarService`; homepage V1.11 uses **received** task records, not company important tasks. Check task-map shape and identity-filtering; mobile intentionally filters `PERSONAL` items locally. |
| Daily items | No server calls in current mobile, only user-id keyed `shared_preferences` | Optional proposed `/daily-items` CRUD requires separate client opt-in and migration policy; do not claim cross-device sync on this release. |

The mobile `ApiRepository` uses `page=1,size=50` up to ten pages for list endpoints, expects `items` arrays (or direct array for some endpoints), and rejects nonzero `code`. Response field names and status enums must match the mobile model parsers before marking contract fixtures complete. Badge read state is tracked in `task_read_tracker.dart` locally; server persistence is not currently a client requirement.
