# 潘多拉 Pandora · V1.4 局部交互调整说明

基于 V1.3.0 完整 Flutter 源码，并合并上一轮“测试与刷新补丁”的修正。

## 甲方要求与本次对应改动

1. **导图**：固定布局为一屏四宫格，页面不再整页滚动；四个面板分别滚动、默认只露出几条；每个最多读取 10 条。顶部仅提供标题和刷新，四宫格之外不增加业务板块。四宫格较窄，因此文本每条最多显示两行标题及一行摘要。
2. **视图 → 日历**：周/月视图同一天同时出现超过三项任务时，第三条以后的任务被折叠，周内出现可点击的「查看更多任务」文字，进入独立完整甘特图页面；日视图也只展示前三条并提供同样文字入口。
3. **视图 → 下属动态**：点击成员头像进入“下属个人信息”页面，展示该成员已授权返回的组织资料、全部已返回任务及可查看日志。不可越权查看密码、隐私点评或未获授权的资料。
4. **日志**：在原“部门日志 / 我的日志”之外，团队长、部门老总、创始人可切换到独立的“我的下属”；依据后端下属名单按员工 ID 筛选，然后还能点选某个下属；与部门筛选不会互相污染。

## 后端联调依赖（重要）

- “我的下属”和“下属动态”依赖现有预留的 `GET /api/tasks/subordinates/overview`。返回的 `userId` 应覆盖当前账号有权管理的**全部成员，包括零任务成员**，而不是只返回有任务的员工。并要求由服务器校验组织权限。
- 可选的更多下属资料字段：`role`、`teamName`、`username`。没有返回的字段在界面不显示，绝不臆造。若要增加联系方式等敏感字段，必须设计独立权限控制和接口，当前版本不会公开。
- 具体日志范围以 `GET /api/logs` 的服务端授权结果为准。前端仅在已授权数据上进一步筛选，不能代替服务器校验。
- 公司四大面板仍依赖后端 `/company-matters`、`/company-important-tasks`、`/logs`。其中“个人十大信息”沿用 V1.3 的个人日志摘要作为占位信息源；如需业务级个人十大消息，请后端提供专用接口及聚合规则。
