# 中国大陆动态节假日日历接口契约（移动端 v1.14）

## 目标与边界

- 移动端只通过自己的后端获取 **中国大陆** 法定放假、调休补班、传统节日；不得把未来年份的放假安排写死在 Flutter 源码中。
- 节假日仅是**日历展示数据**，与公司任务和首页私人每日事项（Todo）完全无关联。后端节假日接口不得返回个人事项，也不得擅自创建任务。
- 后端负责可信数据源的接入、官方安排校验、增量同步、缓存与公布状态维护。Flutter 不直接请求第三方节假日网站。
- 传统节日和放假性质相互独立：传统节日不自动等于放假日；普通周末也不自动标记为国家规定的“休”。

## API

```http
GET /api/calendar/holidays?year=2027
Authorization: Bearer <access-token>
Accept: application/json
```

成功响应沿用当前后端统一协议 `code == 0`：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "year": 2027,
    "region": "CN",
    "timezone": "Asia/Shanghai",
    "dataStatus": "published",
    "lastSyncedAt": "2026-11-11T08:00:00+08:00",
    "days": [
      {
        "date": "2027-01-01",
        "dayType": "holiday",
        "holidayName": "元旦",
        "festivals": ["元旦"],
        "sourceUrl": "https://example.gov.cn/official-notice"
      },
      {
        "date": "2027-03-01",
        "dayType": "normal",
        "holidayName": "",
        "festivals": ["示例传统节日"]
      }
    ]
  }
}
```

> 上述日期/节日仅为 **字段格式演示**，不是经过核验的实际官方假期表。`sourceUrl` 应填写真实的政府通知链接而不是示例 URL。

### 字段约定

| 字段 | 必填 | 解释 |
|---|---|---|
| `year` | 是 | 查询年份，须和 `year` 查询参数一致 |
| `region` | 是 | 固定为 `CN` |
| `timezone` | 是 | 固定为 `Asia/Shanghai` |
| `dataStatus` | 是 | `published` / `partial` / `not_published` / `unavailable` |
| `lastSyncedAt` | 推荐 | 上游数据最后成功同步时间，ISO8601 带时区 |
| `days` | 是 | 数组；每个日期最多一条记录，合并节日和放假属性 |
| `days[].date` | 是 | `YYYY-MM-DD`，按中国日历日期 |
| `days[].dayType` | 是 | `holiday` 法定或调休放假、`makeup_workday` 调休补班、`normal` 正常日期 |
| `days[].holidayName` | 是 | 官方假期名称；无则空字符串 |
| `days[].festivals` | 是 | 传统节日名数组，可为空，多个节日可共存 |
| `days[].sourceUrl` | 可选 | 放假安排对应的官方通知链接 |

`dataStatus` 语义：

- `published`：该年份正式放假安排已公布，并已核验。
- `partial`：例如仅同步了部分日期或传统节日，不能声称完整的全年法定安排。
- `not_published`：全年安排尚未公布，**不是“没有节假日”**，`days` 可以仍含已知传统节日。
- `unavailable`：数据源尚未接入 / 无法确认；不能把它当成 `published`。

建议后端额外存储源 URL、同步结果、上游版本及失败原因，防止第三方变更造成错误日期；公布未确定时不要自动推算国务院调休。

## Flutter 当前实现

- `ApiRepository.holidayYear`：使用已有鉴权和统一 `{code, message, data}` 请求流程，请求 `/calendar/holidays`。
- `HolidayCalendarService`：两个日历共享；按年缓存 JSON，12 小时内复用；用户刷新时强制请求；失败时使用最近一次成功的数据，并告知可能过期。
- 月历单元格显示：`休`、`班` 小标签 + 节日名称；选中日期显示节日文字。任务和私人 Todo 继续使用自己的数据存储。
- 后端尚未部署 / 返回 404：移动端只显示“节假日暂不可用”并提供重试；不会生成“内置假期”。
- `PANDORA_DEMO=true`：演示仓库不内置假日表，返回 `unavailable` 状态。

## 联调检查

1. 确认后端实际监听端口（此前 Windows `8080` 曾检查失败，不能假设一定为 8080）。
2. 验证 `GET /api/calendar/holidays?year=2027` 在登录后返回 `code:0`，且 `data.year` 与请求相同。
3. 用年度包含法定假日、调休补班、仅传统节日的三种日期验收 `休/班/节日名称`。
4. 模拟断网，检查缓存和“离线缓存，可能尚未更新”提示。
5. 模拟未公布年份，显示“尚未公布”，而不是伪造全年安排。
6. 确认切换到下一年与月末跨年时，无重复节日、无任务/个人 Todo 数据串用。
