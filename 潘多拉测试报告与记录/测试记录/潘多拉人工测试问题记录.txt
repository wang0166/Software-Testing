WEB-001　点击弹窗外部导致新增或编辑用户时丢失未保存内容

发现方式　用户人工测试，附截图。已核对本地 main 98f381b 的关闭逻辑。
模块　Web 管理端 → 用户管理 → 新增用户、编辑用户。
复现步骤　用管理员账号打开「新增用户」，填写部分字段，暂不保存。点击弹窗外侧灰色遮罩，例如截图圈出的位置。再次点「新增用户」，检查先前填写的内容。
实际结果　弹窗直接关闭，已填写内容没有保存。源码确认遮罩点击会调用关闭处理，并将表单恢复为空白。
预期结果　点击遮罩时弹窗保持打开，已填写内容保留，可以继续填写。主动放弃填写时，通过底部「取消」关闭。正常点击「保存」并成功提交后关闭。
建议复测　分别点击左右侧遮罩、按 Esc、检查右上角关闭入口。未保存时，底部「取消」是唯一的主动取消入口。再验证底部「取消」能关闭并清空，以及保存校验失败时表单继续保留。
影响　误点击弹窗外侧即可丢失录入内容，管理员需要重新填写。
状态　已记录，待修复和复测。Esc 和右上角 × 经源码核对会触发同一关闭逻辑，当前截图对应的是遮罩点击问题。

WEB-002　新增用户的姓名允许含非法符号的内容通过

发现方式　用户人工测试，附新增表单和保存后列表截图。已核对本地 main 98f381b 的前后端校验。
模块　Web 管理端 → 用户管理 → 新增用户。编辑用户使用相同的姓名格式校验，列入复测。
复现步骤　打开「新增用户」，姓名输入「&ww」，其余必填字段使用有效的测试资料，点击「保存」，再查看用户列表。
实际结果　用户截图显示「&ww」已作为姓名出现在用户列表。页面检查非空、最多 64 个字符、至少包含一个文字字符且不含控制字符。英文字母 ww 满足文字要求，因此前端仍允许这个包含 & 的输入。后端新增与编辑对姓名只校验非空和长度。
预期结果　接受符合姓名规则的汉字输入。输入「&ww」或含非法符号、数字、表情的内容时，姓名字段提示格式错误，表单保留，账号不创建。编辑接口应按同一规则拒绝非法姓名。
建议复测　正常汉字姓名「张三」、复姓「欧阳娜娜」可保存。分别验证「&ww」「张&三」「张3」「张😀」和纯空格被拒绝，校验失败时列表无新增记录，编辑失败时原姓名保留。少数民族姓名中的间隔号及外文姓名是否允许，由业务规则确认。
影响　无效姓名可以进入人员列表，影响身份识别和人员查询。
状态　已记录，待修复和复测。新增问题由用户截图确认，编辑路径经源码核对，待操作复测。

WEB-003　事件纪显示顺序可输入 0 或负整数

发现方式　用户人工测试，附编辑事件截图。本地 main 98f381b。
模块　Web 管理端 → 事件纪 → 编辑事件 → 显示顺序。新建事件使用同一字段，列入复测。
文档依据　原始《智能掌上日志系统-潘多拉》PDF 第 5 页提出展示公司十大重要事项，未规定排序取值。《后端接口文档》第 9.2 节只写「排序为整数」，未设正数下限。《技术设计文档》将 company_matters.sort_order 定义为 INT，默认值为 0。
实际结果　第一张截图中显示顺序可填写 -2，保存后是否保留待复测。第二张截图显示输入 3.5 时，页面提示「请输入 -2147483648 到 2147483647 之间的整数」，小数校验已触发。源码核对显示前端允许有符号的 32 位整数，后端目前也没有正整数下限。
建议规则　显示顺序若按从 1 开始的顺序编号使用，最小值设为 1，前端和后端统一要求正整数。输入非法值时提示「请输入大于 0 的整数」并保留表单。上限及历史非正值的兼容处理由小组确认。
复测用例　分别提交 -2、-1、0、1、2、3.5、空白，核对提示和刷新后的排序。规则确认后，按新的最小合法值 1 验证其前后值。
状态　排序规则待小组确认。当前字段实际按数值从小到大排序。

E2E-002　已派发任务删除提示中的审批角色与后端规则不一致

发现方式　用户核对系统管理员能否删除已派发任务。已对照本地 main 98f381b 的 App 提示、设计文档和服务端审批逻辑。

复测用例　验证待审批与驳回后原任务仍可查询，批准后任务消失。另核对系统管理员无直接删除权限，Web 操作记录可只读查看相应审计记录。
状态　已确认文案与实现不一致。管理员无直接删除权限符合现有设计。
