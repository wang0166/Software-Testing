潘多拉真机边界测试
日期　2026-11-26
设备　Redmi K70 Ultra
版本　main d257b47，独立安装的「潘多拉·验收」，独立本地 Spring Boot/PostgreSQL。

执行方式　使用 Flutter 应用内真机测试操作实际控件和接口。测试使用本地演示账号和专用记录。
最终结果　8 条中 6 条通过、2 条失败。首轮 4 条完整通过，余下 4 条调整滚动和等待逻辑后，在重获手机单次 USB 安装授权时完成复跑。

DEVICE-QA-01　登录校验　通过
输入　空格账号及空密码、正确账号搭配错误密码、正确账号和密码。
预期　前两组被拦截，正确密码进入首页。
实际　页面提示填写账号和密码；错密码提示用户名或密码错误；正确密码进入首页。

DEVICE-QA-02　日志日期、空白、草稿、提交　通过
输入　当天日志，纯空格正文，随后改为真机测试正文。
预期　日期可选窗口为今天及前两天。空白被拦截。保存后重开，正文一致。正式提交后为已提交。
实际　可选窗口符合预期，空白显示「日志内容不能为空」。有效正文保存后回到列表，重新打开正文一致，手动提交后详情显示「已提交」。后端只查到一条对应记录，状态 SUBMITTED 且有提交时间。

DEVICE-QA-03　个人事项字符上限　通过
输入　纯空格标题，101 字标题、501 字备注。
预期　空白提示必填。输入框最多保留 100 字标题、500 字备注，保存后的数据长度一致。
实际　空白被拦截，输入截断后保存成功。后端查到一条对应事项，标题 100 字、备注 500 字。

DEVICE-QA-04　交接缺字段及取消确认　通过
输入　不选接手人，选接手人但说明全为空格，补齐说明后在确认框取消。
预期　前两项应提示原因，取消后应保留表单和未提交内容。
实际　页面提示选择在职接手人和填写说明。取消确认后保留表单和说明文字。后端相关任务仍待交接、无新分配。

DEVICE-QA-05　交接说明 1001 字　拦截通过
输入　选有效接手人，保持原截止时间，输入 1001 个汉字。
预期　拒绝超长说明，留在表单，不生成新任务分配。
实际　显示「交接失败：参数校验失败」，留在表单。后端待交接，原进度 45%，无新任务分配。提示只报通用错误，用户无法从提示得知 1000 字限制。

DEVICE-QA-06　交接改期　失败（E2E-003）
输入　在日期选择器把原截止日期改为 2026-12-05，确认交接。
预期　选出的有效日期能提交。
实际　本轮真机选中 2026-12-05 后确认，再次显示「交接失败：参数校验失败」。后端仍待交接。

DEVICE-QA-07　交接说明 1000 字及新负责人回读　失败（E2E-006）
输入　保持原截止时间，填 1000 字说明，选择新接手人。
预期　确认交接成功，新负责人在收到的任务中看见该任务。
实际　真机确认后仍停留在表单，后端保持待交接，无新分配。数据库日志显示合并进度备注长度超限。
接口对照　另一条同条件测试任务中，提交 982 字返回 HTTP 409、业务码 40909，提交 981 字成功。后端拼接 19 字后，最终备注实际分别为 1001 字和 1000 字。

DEVICE-QA-08　异团队组长可见范围　通过
输入　异团队组长登录，从任务清单选择「待交接」。
预期　看不到其他团队的待交接任务。
实际　页面显示「暂无待交接任务」，平台研发组的测试任务未显示。

安装复查　手机日志显示 USB 安装开关已开启，澎湃 OS 仍会打开单次 USB 安装确认页。重连并确认后，测试包安装成功，4 条补测均已执行。
恢复普通包　测试结束后的 USB 恢复尝试被系统拒绝。用户随后从手机「下载/Pandora-d257b47-QA.apk」安装恢复。已核对手机应用的 SHA-256 与普通验收包一致，USB 到本地后端的健康检查返回 HTTP 200、UP。
