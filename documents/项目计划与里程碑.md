# 项目计划与里程碑 —— 智能掌上日志系统（潘多拉 Pandora）

## 1. 计划说明

### 1.1 时间基准

- 项目第一周开始于 2026-09-18（周五）。
- 开发阶段共 10 周：2026-09-18 至 2026-11-26。
- 测试阶段在开发完成后 6 周内完成：2026-11-27 至 2027-01-07。
- 每个迭代为一个 7 天 Sprint，从周五开始、下周四结束。

### 1.2 敏捷原则

- 以 7 天 Sprint 为节奏，每个 Sprint 结束都要有可演示、可运行、可验收的增量。
- 测试左移：测试从第 1 周就开始编写用例，不把测试全部压到最后。
- 后端先定接口契约，移动端和 Web 端用 Mock 数据并行开发。
- 权限规则统一由后端定义，前端只负责展示与路由控制。
- 持续集成与验收证据：每个任务必须有运行结果、测试结果或可核验提交记录。

### 1.3 团队与分工

老师担任项目经理与产品经理，需求、产品与项目管理由老师负责。团队中的五名学生按岗位分工：

| 岗位 | 职责 |
|---|---|
| 前端 | Web 管理端：React 页面、用户/组织/角色/配置、日志与统计只读、公司十大重要事项维护 |
| 后端 | Spring Boot + MyBatis + PostgreSQL，接口、业务规则、权限过滤、任务派发/接收/检查、日历聚合、定时任务 |
| 客户端 | Android 移动端：Flutter 页面、登录、日志、查看、点评、统计、导图/视图/个人面板/数据地图、任务分发与接收 |
| 运维 | 数据库设计与迁移、任务表与索引、Docker、CI/CD、联调、发布、文档 |
| 测试 | 测试计划、用例、自动化、缺陷、非功能验证、任务权限与多人隔离专项 |

### 1.4 计划基线与容量说明

- 本文档保持原有 16 个 Sprint、2026-09-18 至 2027-01-07 的总周期，以及 M1–M9 里程碑日期不变。
- 原有日志、点评、统计、组织与权限相关交付全部保留，不因任务管理范围新增而删除或推迟。
- 任务管理、公司展示内容与日历视图通过并入既有 Sprint 的方式安排，未新增 Sprint；该范围增加了后端、客户端、前端与测试工作量，存在容量风险，需在 Sprint 1 结束后复核各 Sprint 负载。
- 本计划为后续工作安排，不表示任何历史任务已经完成；实际完成情况以任务清单与验收证据为准。
