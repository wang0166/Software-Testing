# 移动端新版后端对接与验收

本轮针对移动端分支 `feat/pandora-mobile-redesign` 的 `77ae280` 核对和补齐后端，不包含合并移动端代码、修改 Flutter、实机联调、Web 审核页面或服务器部署。接口实现与部署状态分开，移动端同学负责在实际设备上验收。

## 任务时间与已有数据升级

- `POST /api/tasks` 的 `startDate/deadline` 使用北京时间，格式为 `YYYY-MM-DDTHH:mm:ss`，秒必须为 `00`，也接受省略秒的分钟格式。当前不接受 `Z` 或带偏移的任务时间，避免无声地转换日期。
- 截止时间必须严格晚于开始；可同日、跨日，接收人仍必须是派发人的启用直属下级。
- 收到/派发列表、两种任务详情、任务地图均返回完整时间，地图新增 `startDate`；日历日期查询保留原最多 31 天限制，并正确计入当天稍晚开始、跨日和月末的任务。
- 为兼容旧客户端，纯日期请求仍接受：开始为当天 `00:00`，截止为当天 `23:59`。V8 对历史日期任务采用同样转换，保留原覆盖日期、任务 ID、接收记录和密码，不修改 V1～V7 的历史脚本。
- 公司重要事项使用独立的整点时间契约：北京时间 `+08:00`，不选择分钟，允许同一整点。此次任务分钟精度不改变事项约束。

## 日志组织、点评与截止

`GET /api/logs` 和日志详情在原字段基础上增加 `authorRole`、`departmentId`、`departmentName`、`teamId`、`teamName`。无归属时返回 null；前端可据此分类，但可见范围继续由服务端决定，不能靠前端过滤授权。

- 仅作者与当前直属上级可读点评；其他成员、越级上级及管理员不可读。
- 直属上级发起顶层点评（`parentId` 为空）；作者只能回复同一日志内、当前直属上级发起的顶层点评。不能自行发起、回复自己的回复或跨日志回复；上级不能伪装为作者回复。
- 创建/编辑/提交按服务端 `Asia/Shanghai` 时区检查截止，截止瞬间起拒绝写入。编辑及首次提交还要求日志属于当天，防止次日修改或补交旧草稿；已提交日志仍不可编辑。
- 定时任务默认启动 1 秒后执行，此后每 60 秒结算一次：到达配置截止时间后将当日草稿提交，同时补处理停机期间留下的历史草稿。重复执行幂等，未写日志者不补造记录，统计仍推导其为未提交。
- `submitted_at` 为实际处理时刻，不伪造停机期间的提交时间。定时任务不提供秒级即时调度保证；API 的截止校验即时生效。
- 可通过 `app.log-deadline-job.enabled=false` 在隔离契约测试中禁用调度；生产保持启用。原 `system_configs.log_deadline` 继续有效，不恢复已取消的 Web 配置页面。

## 密码申请与审批接口

均使用通用 `{code,message,data}` 响应。除下表标注的公开接口外需要 Bearer 令牌。新密码至少 8 个字符且 UTF-8 不超过 72 字节，不裁剪密码；原 Web 开户/管理员直接重置的既有 6 位下限保留兼容。

| 方法与路径 | 权限与请求 | 成功行为 |
|---|---|---|
| `POST /api/auth/password-reset-requests` | 公开；`{"username":"账号"}` | 统一受理提示，无账号存在性、申请 ID 或限流命中信息 |
| `POST /api/account/password-change-requests` | 本人登录；空对象即可 | 创建 `PENDING` 修改申请；禁止同类重复待审/已批准申请 |
| `GET /api/account/password-change-requests/me` | 本人登录 | `data.status` 为 `NONE/PENDING/APPROVED/REJECTED`，附 `expiresAt`；已消费/取消/过期映射为 `NONE` |
| `POST /api/account/password-change` | 本人登录；`{"newPassword":"本人输入"}` | 消费本人有效批准，哈希保存新密码并撤销全部旧会话 |
| `GET /api/password-requests` | 管理员且有 `user:manage`；可选 `status/kind/page/size` | 分页查询申请，不返回密码、密码哈希或恢复凭据 |
| `POST /api/password-requests/{id}/review` | 管理员重新验证自己的 `currentPassword`，`decision` 为 `APPROVED/REJECTED` | 不允许自审，批准必须 `identityVerified:true`；不允许重复审核 |
| `POST /api/auth/password-reset` | 公开；`{"token":"恢复凭据","newPassword":"本人输入"}` | 仅有效一次性恢复凭据可用；成功后撤销旧会话，不自动登录 |

申请类型 `kind` 为 `CHANGE/RESET`；原始状态还包括 `CONSUMED/EXPIRED/CANCELLED`，供管理员查询。

### 审批与找回流程

1. 申请有效期 24 小时；批准后只在 15 分钟内有效，凭据只允许消费一次，重复提交或并发审批只有一个成功。
2. 已登录改密沿用移动端现有申请/状态/完成接口，不需要向管理员提交新密码。管理员核实本人身份后批准，申请人自己设置新密码。
3. 忘记密码仅凭账号名只能申请，不能直接改密。管理员必须通过组织认可的线下/受控渠道核实身份，再使用审核接口批准 `RESET`；批准响应中一次性返回 `recoveryToken`，带 `Cache-Control: no-store`。该值是临时恢复权限，不是新密码，不能放入日志、列表、截图、工单或公开聊天；只能通过核验后的受控渠道交给本人。
4. 申请人以恢复凭据调用公开完成接口并自行设置密码；服务端只存凭据 SHA-256 摘要，消费后删除摘要。当前没有邮件/短信服务，也没有移动端恢复凭据输入页，不能声称申请后会自动发送链接或已完成整个客户端找回流程。
5. 管理员直接重置、账号状态/资料变化等造成 `auth_version` 改变后，旧批准立即失效。改密成功会撤销访问和刷新会话，移动端应清除旧登录状态并返回登录页；不要成功后继续用旧令牌刷新审批状态。
6. 数据库限流以 15 分钟为窗口：公开申请/恢复完成按账号或凭据 5 次、按来源地址 30 次；审核每管理员 20 次。公开申请超限仍统一受理提示并抑制写入，恢复/审核超限返回 `42901`。只使用实际连接地址，不自行信任 `X-Forwarded-For`；多实例共享数据库计数，失败业务回滚不清除限流计数。
7. 审计记录申请、批准/拒绝、完成及失败状态，不读写请求正文、新密码、原密码、令牌或身份核验材料。身份核验布尔值是管理员的操作确认，不能替代现实身份核实；不自动发送任何通知。

补充错误码：`40920` 申请重复/过期/已处理，`40320` 缺少有效改密批准，`40020` 恢复凭据无效/过期，`42901` 请求过频。错误仍使用对应 HTTP 400/403/409/429，不以模拟成功替代失败。

实现参考 [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)：统一提示、限制请求、强随机单次过期凭据和受控交付；本项目没有引入外部代码或额外依赖。

## 移动端与部署交接

- 移动端同学使用真实模式，核对分钟任务派发/刷新/日历、日志部门团队分类、直属上级点评、截止与跨日，以及改密后退出重新登录。Web 审批 UI 尚未新增，可由授权管理员通过审核 API 验收；不要在 App 内模拟批准。
- 公司事项后端已有 `sortOrder`、起止时间；移动端当前 `CompanyItem` 只读取标题与内容，若要显示时间需要客户端接入这些字段。
- `company-important-tasks` 仍是独立的公司展示内容，不自动等于普通派发任务；创始人维护方式尚未确认，未擅自新增管理入口。头像跨设备同步、真正 AI 推理和个人重点信息维护也不在本轮。
- 部署前备份数据库并检查 Flyway 历史；标准 V7 只新增 V8，标准 V6 依次应用 V7/V8。旧本机测试库继续由本地兼容启动器处理，不把本机数据库或兼容目录复制到服务器。
- 后端自动化验收在隔离 PostgreSQL 上运行；实机、真实网络、服务器升级后的验收由相应同学完成，本地自动化不代表这些检查已通过。
