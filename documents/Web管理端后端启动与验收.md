# Web 管理端后端启动与验收

本轮提供用户与组织管理、团队人员、审计及公司事项读写。代码状态与服务器部署状态独立；本地验证通过不代表已部署。角色权限配置、系统配置页面和用户/事项删除不在本轮交付范围。

## 本机运行：无需另装数据库

前提：JDK 17 或以上、Maven、项目现有依赖可用。启动器使用 pom.xml 已有的 test scope embedded-postgres 2.1.0，不新增生产依赖；首次缺缓存时 Maven 可能联网下载原有依赖与当前平台的 PostgreSQL 组件。

在项目根目录运行：

```powershell
.\tools\start-local-backend.ps1
```

若 Maven 不在 PATH，可通过 `-MavenCommand '<Maven目录>/bin/mvn.cmd'` 指定已有 Maven；需要特定缓存时加 `-MavenRepository '<本机Maven仓库>'`。无需修改全局 PATH 或安装新 Maven。

- 初次启动安全输入管理员初始密码，不回显、不写入文件；也支持使用进程环境变量 ADMIN_INIT_PASSWORD。默认账号 admin，ADMIN_INIT_USERNAME 可自定义。
- 默认 API 为 http://127.0.0.1:8080/api，健康检查为 /actuator/health；后端和临时 PostgreSQL 都只监听本机，启动器强制使用其独立数据库，忽略外部数据库连接变量。
- 默认数据目录为项目个人资料/开发/本地后端，已由现有 Git 忽略保护；同一目录重启保留数据，不清库、不重新覆盖已存在的管理员密码。`-DataDirectory` 和 `-Port` 可显式修改。
- 启动器每次生成新的本地 JWT 签名密钥，重启后需重新登录。运行类路径保存在个人资料/开发/验证，不放进 initdb 要求为空的新数据库目录。
- 数据目录仅本机开发使用，不提交、打包或传给服务器同学；生产 JAR 不包含启动器和嵌入式数据库。
- 首次交付前曾在本机执行过 V6 Web 迁移的开发库，启动器会使用独立兼容目录保留其 V6 历史，再应用完整性约束，不改历史或校验和。服务器始终按标准 V6 完整性约束、V7 Web 扩展执行，不能把本地库或其迁移历史直接复制到服务器。

在另一个终端正常停止，同样传入自定义的数据目录（如使用过）：

```powershell
.\tools\start-local-backend.ps1 -Stop
```

脚本写入停止标记，启动器关闭 Spring Boot 和 PostgreSQL，保留数据库文件。不要在服务运行时删除数据库目录。异常终止后，先确认原进程是否仍运行，再按错误提示处理遗留锁或停止标记，不直接重建覆盖。

## 前端连接

运行后端后，在 pandora_web 启动 `npm run dev`，访问默认端口 5174。退出演示账号，在登录页取消勾选演示模式，使用实际管理员账号和初始化时设置的密码。

本地代理目标为 http://127.0.0.1:8080，VITE_API_BASE 保持 /api；后端使用其他端口时，调整进程环境变量 VITE_PROXY_TARGET 后重启 Vite。个人 .env.local 不提交。本轮前端已经开放已交付能力，连接旧后端时会真实报错。

## 服务器交接

1. 运维提供 PostgreSQL 数据库、连接用户与密码；后端配置 SPRING_DATASOURCE_URL、SPRING_DATASOURCE_USERNAME、SPRING_DATASOURCE_PASSWORD、JWT_SECRET、ADMIN_INIT_PASSWORD，敏感值由安全配置渠道提供。
2. `mvn test` 验证后执行 `mvn package`，运行 `java -jar target/pandora-log-backend-0.1.0-SNAPSHOT.jar`。Flyway 按顺序应用 V1～V7，已有标准 V6 数据库只应用 V7，V5 数据库依次应用 V6/V7；不改旧迁移、不清历史数据。
   - 服务器已有数据库时，先备份并检查 flyway_schema_history 的最近版本与迁移状态，再启动升级。
   - 如果是手工建表或没有 Flyway 历史，先对照 V1～V5 核对实际表结构，由部署同学确认接管方案；不要直接启用 baseline 或 clean，也不要删表重建。
   - V6 会检查用户角色字典、团队与部门一致性、父评论所属日志及提交时间；若已有数据不满足约束，先确认修复方案，不通过清库或伪造时间跳过。
3. V5 原有固定密码演示账号不能直接用于公开部署；上线前由管理员重置或停用。生产 JWT_SECRET 应稳定保管，不能使用本地启动器的临时密钥或测试参数。
4. 配置 HTTPS 与前端 /api 反向代理；本地开发连接远程测试服务时将 VITE_PROXY_TARGET 指向实际服务器，保留 /api，重启前端。不把内网代理地址硬编码到源码。
5. 检查健康状态、管理员登录及下列验收流程。服务器地址、防火墙、数据库备份和实际部署均由部署阶段核实，本轮未执行服务器操作。

## 验收重点

- 新开户：手机号填入、手改账号、生成初始密码；保存后可用最终账号与密码登录，列表/详情资料来自数据库，响应不含密码或哈希。
- 用户查询：跨页搜索、角色/状态/团队筛选、总数与空列表；编辑后查询回显，密码重置、启停和资料变更使旧会话失效，至少保留一个启用管理员。
- 组织：真实公司 ID、部门/团队介绍、同上级名称查重、负责人唯一性；团队换负责人时同步旧角色；带成员或下级组织不能删除或迁移。
- 事项：开始/截止精确到小时，可同一整点、跨日；非法日期、非整点、浮点排序与倒序返回 400；保存刷新后仍存在，历史空值不补造时间。
- 审计：操作者/动作/时间范围分页查询，成功和失败可区分，详情只读，不保存请求正文、密码、令牌或身份资料。
- 权限：未登录 401，非管理员管理请求 403，重复/关联冲突 409，参数错误 400；真实失败不回退演示或伪造成功。

本轮 60 项后端测试包含真实 PostgreSQL 契约、V5→V7/标准 V6→V7 升级、旧本地 V6 校验和保留与并发负责人测试；浏览器通过实际 HTTP 连接后端完成主要流程。仍需服务器部署后的环境复验。
