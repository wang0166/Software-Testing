# Pandora 后端 REST API 接口文档

> 版本：MVP 草案（依据 `documents/产品需求文档.md`、`documents/顶层设计文档.md`、`documents/技术设计文档.md` 编制）  
> Base URL：`/api`（本地默认 `http://localhost:8080/api`）  
> 适用端：Flutter Android、React 管理端、QA API 契约测试

## 1. 范围与约定

本接口覆盖登录认证、用户与组织管理、工作日志、直属上级点评、统计、系统配置和审计查询。AI 摘要、通知、离线填报、数据导出不属于本期。

除登录、刷新令牌外，接口均须携带 `Authorization: Bearer <accessToken>`。请求和响应使用 UTF-8 JSON；日期使用 `YYYY-MM-DD`，时间戳使用 ISO-8601，业务时区统一为 `Asia/Shanghai`。服务端从令牌识别当前用户，任何 `authorId`、`teamId`、`departmentId` 查询条件都不能扩大服务端计算出的可见范围。

### 1.1 统一响应

成功响应：

```json
{"code":0,"message":"ok","data":{}}
```

分页列表的 `data`：

```json
{"items":[],"page":1,"size":20,"total":0}
```

错误响应：

```json
{"code":40301,"message":"无权访问该日志","data":null}
```

HTTP 状态码表达协议层结果（400/401/403/404/409/422/429/500）；`code` 是稳定的业务错误码。字段校验错误可在 `data.errors` 中返回字段到错误信息的映射。服务端不得向客户端返回密码哈希、刷新令牌哈希或内部异常堆栈。

### 1.2 身份与数据范围

| 身份 | 日志范围 | 点评关系 | 管理能力 |
|---|---|---|---|
| `EMPLOYEE` | 自己 | 回复直属上级 | 无 |
| `TEAM_LEADER` | 所属团队 | 点评团队成员 | 无 |
| `DEPT_MANAGER` | 所属部门 | 点评团队负责人 | 无 |
| `FOUNDER` | 全公司 | 点评部门负责人 | 无 |
| `ADMIN` | 全公司只读 | 不参与点评 | 用户、组织、角色权限、配置、审计 |

一个用户只有一种角色。员工和团队负责人必须属于一个团队；部门负责人属于一个部门；创始人和系统管理员不属于团队或部门。管理员虽可读取全公司日志和统计，但不能写入或修改日志。

## 2. 认证

### `POST /auth/login`

登录，不需要令牌。

```json
{"username":"zhangsan","password":"secret"}
```

成功返回 `accessToken`、`refreshToken`、`tokenType`、`expiresIn` 和 `user`（`id`、`username`、`realName`、`role`、`departmentId`、`teamId`）。停用或锁定账号拒绝登录；连续失败按安全配置锁定，成功后清零失败次数。

### `POST /auth/refresh`

```json
{"refreshToken":"..."}
```

校验刷新令牌并返回新的访问令牌。令牌轮换策略需在实现前确定（见第 10 节）。

### `POST /auth/logout`

```json
{"refreshToken":"..."}
```

撤销该刷新令牌/会话，成功后重复调用应幂等。

### `GET /auth/me`

返回当前账号摘要、角色、组织归属和可用权限码。账号权限以服务端为准。

## 3. 用户、组织、角色与权限（管理员）

以下接口要求管理员身份及对应管理权限；列表均分页，最大 `size` 暂定 100。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/users` | 按关键字、`role`、`status`、`departmentId`、`teamId` 筛选用户 |
| `POST` | `/users` | 创建账号并分配唯一角色及合法组织归属 |
| `GET` | `/users/{id}` | 用户详情（不含凭据） |
| `PUT` | `/users/{id}` | 编辑姓名、角色、组织归属等资料 |
| `PATCH` | `/users/{id}/status` | 启用/停用 |
| `PUT` | `/users/{id}/password` | 管理员重置密码 |
| `GET` | `/companies/{id}` | 查询公司信息 |
| `PUT` | `/companies/{id}` | 编辑公司资料 |
| `GET/POST` | `/departments` | 部门列表/创建 |
| `GET/PUT/DELETE` | `/departments/{id}` | 部门详情/编辑/删除 |
| `GET/POST` | `/teams` | 团队列表/创建 |
| `GET/PUT/DELETE` | `/teams/{id}` | 团队详情/编辑/删除 |
| `GET` | `/roles` | 角色列表 |
| `GET` | `/permissions` | 权限码清单 |
| `PUT` | `/roles/{code}/permissions` | 设置角色权限 |

创建用户示例：`{"username":"lisi","password":"...","realName":"李四","role":"TEAM_LEADER","departmentId":3,"teamId":8}`。团队负责人必须与团队及部门关系一致；员工/负责人角色变更时必须校验归属约束。密码使用 BCrypt 存储。删除组织时若仍有成员或下级组织，拒绝删除并要求先迁移归属。

## 4. 工作日志

日志对象字段：`id`、`authorId`、`logDate`、`content`、`status`（`DRAFT`/`SUBMITTED`）、`isImportant`、`submittedAt`、`createdAt`、`updatedAt`。日期由服务端按上海时区生成，客户端不得指定历史或未来日期。内容为非空自由文本。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/logs` | 在当前角色可见范围内查询；可选 `date`、`status`、`authorId`、`page`、`size` |
| `GET` | `/logs/{id}` | 查询单篇日志，执行同等范围校验 |
| `POST` | `/logs` | 为当前用户创建当天草稿，body：`{"content":"..."}` |
| `PUT` | `/logs/{id}` | 作者在截止时间前编辑 `DRAFT` 内容 |
| `POST` | `/logs/{id}/submit` | 作者提交草稿；重复提交按幂等成功或 409（团队统一约定） |
| `POST` | `/logs/{id}/important` | 直属上级标记/取消重点，body：`{"isImportant":true}`（P1 可选） |

业务约束：每人每天最多一篇；内容不得为空；创建时服务端设置当天日期；提交后永久不可修改；截止时间默认 22:00，可由管理员配置。截止后禁止新建、编辑、提交。截止任务将已有草稿转为 `SUBMITTED`；当天无日志的人不落库，统计时推导为未提交。写操作使用事务并保证并发下唯一约束生效。

## 5. 点评对话

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/logs/{id}/comments` | 仅日志作者和作者的直属上级可读 |
| `POST` | `/logs/{id}/comments` | 直属上级发起、作者回复 |

请求：`{"content":"请补充风险项。","parentId":null}`。回复时 `parentId` 指向被回复的点评。发起人必须是该作者的直接上级；回复人必须为日志作者；其他团队成员、越级上级和管理员均不可查看或参与。评论内容不能为空。

## 6. 统计

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/stats/overview` | 应提交人数、已提交人数、提交率、未提交人数 |
| `GET` | `/stats/unsubmitted` | 当前范围未提交人员名单 |
| `GET` | `/stats/counts` | 日/周/月日志数量，参数 `from`、`to`、`groupBy` |
| `GET` | `/stats/trend` | 近 7/30 天趋势，参数 `days=7|30` |
| `GET` | `/stats/important` | 重点日志列表（P1，可选） |

当前用户统计范围与其日志读取范围一致。应提交人数为范围内需写日志的启用用户数（不含管理员）；已提交人数为当天存在 `SUBMITTED` 日志的用户数（含截止任务自动提交的草稿）；未提交人员为应提交用户中当天无已提交日志者；提交率 = 已提交人数 / 应提交人数，应提交人数为 0 时返回 0。

## 7. 配置与审计（管理员）

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/configs` | 查询系统配置 |
| `PUT` | `/configs/{key}` | 更新允许修改的配置；`log_deadline` 示例值 `21:30` |
| `GET` | `/audits` | 按操作者、动作、时间范围分页查询审计记录 |

关键管理操作记录操作者、动作、目标、时间和结果，不记录明文密码或令牌。审计记录只读。配置时间使用 `HH:mm`，校验合法时分。

## 8. 错误码

| HTTP | 业务码 | 含义 |
|---|---:|---|
| 400 | `40001` | 参数校验失败/内容为空 |
| 401 | `40101` | 用户名或密码错误 |
| 401 | `40102` | 访问令牌无效或过期 |
| 401/423 | `40103` | 账号锁定或停用 |
| 403 | `40301` | 无权访问该日志/资源 |
| 403 | `40302` | 非直属上级，不能点评 |
| 404 | `40401` | 资源不存在或不可见（避免泄漏存在性，策略待定） |
| 409 | `40901` | 当天已存在日志 |
| 409 | `40902` | 已提交日志不可修改 |
| 409 | `40903` | 已过截止时间 |
| 409 | `40904` | 组织仍有关联成员，不能删除 |
| 429 | `42901` | 登录尝试过于频繁 |
| 500 | `50000` | 服务内部错误 |

## 9. 安全、并发与审计要求

- 密码仅以 BCrypt 哈希保存；生产环境只经 HTTPS 传输；JWT 密钥通过环境变量注入。
- 认证、角色权限与数据范围在服务端统一执行；高风险越权不得只依赖前端隐藏页面。
- 日志日唯一键由数据库约束保障；提交使用条件更新或等效并发控制；截止任务必须幂等。
- 登录失败次数/锁定、账号启停、用户与组织变更、角色权限与配置变更写审计日志。
- 列表查询强制分页，`size` 最大值 100；排序字段需白名单化。
- API 契约测试覆盖未登录、越权、截止边界、并发重复创建/提交、评论隐私和管理员只读。

## 10. 待确认项

1. 刷新令牌是否轮换、过期时间、单设备/多设备会话和撤销数据模型。
2. 全量 HTTP 状态码映射、统一字段校验结构和 404/403 隐匿策略。
3. 分页及排序参数命名、日志/评论内容长度上限。
4. 组织删除采用硬删除还是软删除；现有设计倾向外键 RESTRICT。
5. `isImportant` 是否纳入 MVP（当前计划标记为可选 P1）。
6. 统计范围内账号是否排除停用用户；建议仅统计启用且需写日志的角色。
7. 管理员角色权限是否允许在 Web 配置，还是角色权限码由系统固定种子数据管理。
